## 빅데이터 개요 및 활용

### 데이터 특징

단순한 객체로도 가치가 있으며, 다른 객체와의 상호관계 속에서 더 큰 가치를 갖는다.

**`데이터의 존재적 / 당위적 특성`**

| 특성        | 특징                               |
| ----------- | ---------------------------------- |
| 존재적 특성 | 객관적 사실                        |
| 당위적 특성 | 추론, 추정, 예측, 전망을 위한 근거 |

### 정량적 / 정성적 데이터

|      | 정량적 데이터(Quantitative Data)                     | 정성적 데이터(Qualitative Data)                                       |
| ---- | ---------------------------------------------------- | --------------------------------------------------------------------- |
| 유형 | 수치, 도형, 기호 등으로 표현되는 데이터              | 언어, 문자 등으로 표현되는 데이터                                     |
| 특징 | 정형화된 값으로 고정된 필드에 저장되어 형식이 일정함 | 정형화되지 않아 형태와 구조가 다양하고 저장·분석에 많은 비용이 발생함 |
| 관점 | 객관적                                               | 주관적                                                                |
| 구성 | 규칙적이고 연속적인 구조                             | 불규칙적인 구조                                                       |
| 형태 | 수치, 숫자, 통계자료                                 | 텍스트, 이미지, 영상, 음성 등                                         |
| 위치 | RDB, 스프레드시트 등 고정된 필드에 저장              | 데이터 자체가 콘텐츠(값)로 저장되어 필드 구분이 없음                  |
| 분석 | 통계 분석                                            | 텍스트마이닝, 감성분석 등 별도 분석기법 필요                          |

### 정형 / 반정형 / 비정형 데이터

|      | 정형 데이터(Structured Data)                                                       | 반정형 데이터(Semi-Structured Data)                                                                                                     | 비정형 데이터(Unstructured Data)                                           |
| ---- | ---------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------- |
| 설명 | 미리 정의된 스키마(고정된 필드)에 따라 저장되는 데이터. 예) RDB, 스프레드시트, CSV | 데이터 내부에 구조(스키마)를 설명하는 메타데이터를 포함하지만 고정된 필드 형태로 저장되지는 않는 데이터. 예) XML, JSON, HTML, 로그 파일 | 정해진 구조(스키마) 없이 저장되는 데이터. 예) 텍스트, 이미지, 음성, 영상   |
| 특징 | 연산 가능하며 정해진 형식과 규칙에 따라 저장·검색·분석이 용이함                    | 연산은 불가능하지만 태그·마크업 등을 파싱하면 구조를 유추할 수 있음                                                                     | 연산 불가능하며 텍스트마이닝, 음성인식, 영상분석 등 별도 분석기법이 필요함 |

### 가역 / 불가역 데이터

|                | 가역 데이터                                                           | 불가역 데이터                                                 |
| -------------- | --------------------------------------------------------------------- | ------------------------------------------------------------- |
| 설명           | 별도의 키나 매핑정보를 이용해 원래 상태로 복원(환원)할 수 있는 데이터 | 한 번 처리되면 원래 상태로 복원이 불가능한 데이터             |
| 환원성(추적성) | 있음 - 키·매핑테이블을 통해 원본 복원 및 추적 가능                    | 없음 - 원본 복원 및 개인 식별 불가능                          |
| 의존성         | 원본 데이터 또는 별도의 키(매핑정보)에 의존적                         | 원본 데이터와 독립적                                          |
| 원본과의 관계  | 원본과의 대응(매핑) 관계가 유지됨                                     | 원본과의 연결고리가 완전히 제거됨                             |
| 처리과정       | 가명처리(치환, 암호화 등)                                             | 총계처리, 삭제, 범주화, 마스킹 등 완전 익명처리               |
| 활용분야       | 통계작성, 연구 등 목적 내 제한적 활용                                 | 개인정보보호법 적용 대상에서 제외되어 자유로운 활용·공개 가능 |

### OLTP / OLAP

| 구분               | OLTP(OnLine Transaction Processing)                                                | OLAP(OnLine Analytical Processing)                                             |
| ------------------ | ---------------------------------------------------------------------------------- | ------------------------------------------------------------------------------ |
| 설명               | 은행, 예약, ERP 등 업무 시스템에서 발생하는 짧고 단순한 트랜잭션을 실시간으로 처리 | 다양한 관점에서 데이터를 다차원적으로 분석하여 의사결정을 지원                 |
| 데이터 구조        | 정규화된 관계형 구조(중복 최소화, 데이터 무결성 중시)                              | 다차원(Cube) 구조, 스타/스노우플레이크 스키마 등 분석에 최적화된 비정규화 구조 |
| 데이터 갱신        | Insert/Update/Delete가 실시간·빈번하게 발생                                        | 정기적(배치)으로 대량 적재, 갱신은 드묾(Read 중심)                             |
| 응답 시간          | 매우 짧음(수 밀리초 단위, 즉각적 처리 요구)                                        | 상대적으로 김(복잡한 집계 연산으로 수 초~수 분)                                |
| 데이터 범위        | 현재 시점의 최신 데이터 위주                                                       | 과거부터 현재까지의 이력(누적) 데이터                                          |
| 데이터 성격        | 운영 데이터(원시 트랜잭션 데이터)                                                  | 분석용 요약·집계 데이터                                                        |
| 데이터 크기        | 트랜잭션 단위로 상대적으로 작음                                                    | 여러 트랜잭션이 누적되어 대용량                                                |
| 데이터 내용        | 최신의 상세(원자 단위) 데이터                                                      | 요약·집계된 다차원 데이터                                                      |
| 데이터 특성        | 동적(수시로 변경됨)                                                                | 정적(한번 적재되면 잘 변경되지 않음)                                           |
| 데이터 엑세스 빈도 | 짧고 단순한 질의가 매우 빈번하게 발생                                              | 복잡한 질의가 상대적으로 드물게 발생                                           |
| 질의 결과 예측     | 사전에 정의된 단순 질의로 결과 예측 가능                                           | 사용자마다 질의가 다양(Ad-hoc)하여 결과 예측이 어려움                          |

### 데이터 웨어하우스(Data Warehouse, DW)

데이터만이 아닌 분석 방법까지도 포함하여 조직 내 의사결정을 지원하는 정보 관리 시스템.

**`DW 특징`**

| 특징                            | 설명                                                                                           |
| ------------------------------- | ---------------------------------------------------------------------------------------------- |
| 주제지향성(Subject-orientation) | 특정 업무(애플리케이션) 단위가 아닌 고객, 상품 등 특정 주제 중심으로 데이터를 구성             |
| 통합성(Integration)             | 여러 운영시스템(원천 데이터)에서 수집한 데이터를 일관된 형식·명명규칙·코드체계로 통합하여 저장 |
| 시계열성(Time-variant)          | 특정 시점의 스냅샷이 아닌 시간의 흐름에 따라 변화하는 데이터를 축적하여 이력을 관리            |
| 비휘발성(Non-volatilization)    | 한 번 적재된 데이터는 삭제·변경되지 않고 읽기(Read) 전용으로 유지됨                            |

**`DW 구성 요소`**

| 구성 요소                     | 설명                                                                                   |
| ----------------------------- | -------------------------------------------------------------------------------------- |
| 데이터 모델(Data Model)       | 데이터를 저장하는 논리적 구조(스타 스키마, 스노우플레이크 스키마 등 다차원 모델링)     |
| ETL(Extract, Transform, Load) | 원천 데이터를 추출(Extract)·변환(Transform)·적재(Load)하여 DW로 옮기는 과정            |
| ODS(Operational Data Store)   | 운영 데이터를 원본과 유사한 형태로 통합 저장해 DW 적재 전 중간 저장소 역할을 하는 영역 |
| Metadata                      | 데이터에 대한 데이터로, 데이터의 구조·의미·출처·변경이력 등을 관리해 DW 활용을 지원    |
| OLAP                          | 적재된 데이터를 다차원적으로 분석하여 사용자의 의사결정을 지원하는 분석 도구/기법      |
| Data Mining                   | 대용량 데이터에서 통계·기계학습 기법으로 숨겨진 패턴이나 규칙을 발견하는 기법          |
| 분석 도구                     | 리포팅, 시각화, 대시보드 등 사용자가 데이터를 조회·분석할 수 있도록 지원하는 도구      |
| 경영기반 솔루션               | DW의 데이터를 경영 전략(BI, CRM, SCM 등) 수립에 활용할 수 있도록 지원하는 응용 솔루션  |

### 빅데이터 5V

| 특징           | 내용                                                                         |
| -------------- | ---------------------------------------------------------------------------- |
| 규모(Volume)   | 기존 방식으로는 처리하기 어려울 정도로 생성·저장되는 데이터의 양이 방대함    |
| 유형(Variety)  | 정형·반정형·비정형 등 다양한 형태와 종류의 데이터가 존재함                   |
| 속도(Velocity) | 데이터가 실시간에 가깝게 빠르게 생성되며, 수집·처리·분석 속도도 빨라야 함    |
| 품질(Veracity) | 데이터에 잡음, 오류, 결측 등이 섞여 있을 수 있어 정확성·신뢰성 확보가 중요함 |
| 가치(Value)    | 데이터 분석을 통해 경제적·사회적으로 의미 있는 가치를 창출할 수 있어야 함    |

### 빅데이터 활용을 위한 3요소

| 요소             | 구체적 요소                                                                                       | 설명                                                                                                                                                                                    |
| ---------------- | ------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 인력(People)     | 데이터 사이언티스트(Data Scientist), 알고리즈미스트(Algorithmist)                                 | 데이터를 수집·분석해 인사이트를 도출하는 전문인력. 데이터 사이언티스트는 통찰력·전달력을 갖춘 분석 전문가이며, 알고리즈미스트는 알고리즘의 편향·오작동 등 부작용을 통제·관리하는 전문가 |
| 자원(Resource)   | 정형, 반정형, 비정형 데이터                                                                       | 분석의 대상이 되는 데이터 자체로, 다양한 원천에서 수집되는 대용량 데이터                                                                                                                |
| 기술(Technology) | 하드웨어(스토리지, 서버 등), 소프트웨어(분석 알고리즘, 통계기법, 시각화 도구), 클라우드 등 인프라 | 대용량 데이터를 수집·저장·처리·분석하기 위해 필요한 기술적 기반                                                                                                                         |

### 데이터 산업의 진화

| 구분             | 특징                                                                                                            |
| ---------------- | --------------------------------------------------------------------------------------------------------------- |
| 데이터 처리 시대 | 컴퓨터 도입 초기 단계로, 개별 업무 시스템 단위에서 데이터를 단순 입력·저장·처리(전산화)하는 데 중점을 둠        |
| 데이터 통합 시대 | 부서·시스템별로 흩어져 있던 데이터를 데이터 웨어하우스 등으로 통합해 전사적으로 공유·관리하기 시작함            |
| 데이터 분석 시대 | BI, OLAP, 데이터마이닝 등을 활용해 통합된 데이터를 분석하고 그 결과를 의사결정에 반영함                         |
| 데이터 연결 시대 | 빅데이터, IoT, 소셜 데이터 등 조직 내·외부의 다양한 데이터를 연결·융합해 실시간으로 대용량 데이터를 처리·활용함 |
| 데이터 권리 시대 | 마이데이터(MyData), 데이터 3법 등을 통해 개인이 자신의 데이터에 대한 자기결정권과 활용 권리를 갖는 것이 중시됨  |

### 데이터 산업의 구조

| 영역        | 특징                                                                                   | 제공 서비스                                                                                                           |
| ----------- | -------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------- |
| 인프라 영역 | 데이터의 생성·수집·저장·처리·분석에 필요한 하드웨어·소프트웨어 등 기술적 기반을 제공   | DBMS, 데이터 웨어하우스/데이터 레이크 구축, ETL 솔루션, 빅데이터 플랫폼, 분석 SW·통계 패키지, 클라우드 인프라 등      |
| 서비스 영역 | 인프라를 기반으로 데이터를 가공·분석하여 기업·개인에게 실질적인 정보와 인사이트를 제공 | 데이터 판매·중개(데이터 거래), 데이터 구축·컨설팅, 데이터 분석·시각화 서비스, 정보 제공 서비스(신용정보, 시장조사 등) |

### 데이터 분석 업무 조직 구조

DSCoE(Data Science Center of Excellence, 분석 전담 조직)

| 조직 구조 | 특징                                                                                                                                                                                                                  |
| --------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 집중형    | 전사 차원의 독립적인 분석 전담 조직(예: DSCoE)을 구성해 회사 전체의 분석 과제를 총괄 수행. 전략적 우선순위에 따라 분석 과제를 신속하게 추진할 수 있으나, 현업 부서의 업무와 분석 업무가 이중화·이원화될 가능성이 있음 |
| 기능형    | 별도의 분석 전담 조직 없이 각 현업 부서가 자체적으로 분석 업무를 수행. 해당 업무 분야에 특화된 분석은 가능하지만, 전사 차원의 우선순위 파악·통합이 어렵고 과거 실적 등 제한된 범위의 분석에 그치기 쉬움               |
| 분산형    | 분석 전담 조직의 인력을 현업 부서에 배치해 분석 업무를 수행. 분석 결과를 업무에 신속하게 반영하고 베스트 프랙티스를 부서 간 공유할 수 있으나, 조직 간 역할이 중복되거나 관리가 어려워질 수 있음                       |

## 빅데이터 기술 및 제도

### 빅데이터 플랫폼

빅데이터 플랫폼은 빅데이터 수집부터 저장, 처리, 분석 등 전 과정을 통합적으로 제공하여 그 기술들을 잘 사용할 수 있도록 준비된 환경을 의미한다.

**`빅데이터 플랫폼 구조`**

| 계층                | 설명                                                                                                                                                            |
| ------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 소프트웨어 계층     | 데이터의 수집·저장·처리·분석·시각화를 수행하는 응용 소프트웨어 및 도구들의 집합(예: 하둡 에코시스템 SW, 분석 SW, 시각화 도구)                                   |
| 플랫폼 계층         | 소프트웨어 계층과 인프라스트럭처 계층을 연결하며, 응용 소프트웨어가 하드웨어 자원을 효율적으로 사용하도록 지원하는 계층(분산 파일시스템, 자원 관리·스케줄링 등) |
| 인프라스트럭처 계층 | 데이터를 저장·처리하는 데 필요한 서버, 스토리지, 네트워크 등 물리적 하드웨어 자원을 제공하는 최하위 계층                                                        |

### 빅데이터 처리과정과 요소기술

| 과정         | 설명                                                                                                      |
| ------------ | --------------------------------------------------------------------------------------------------------- |
| 데이터(생성) | 센서, SNS, 로그, 거래시스템 등 다양한 원천에서 정형·반정형·비정형 데이터가 생성되는 단계                  |
| 수집         | 내부·외부에 존재하는 다양한 데이터를 크롤링, ETL, API, 로그 수집기 등을 활용해 모으는 단계                |
| 저장(공유)   | 수집된 대용량 데이터를 NoSQL, 분산 파일 시스템 등에 저장하고 필요 시 공유할 수 있도록 관리하는 단계       |
| 처리         | 저장된 데이터를 분석 가능한 형태로 정제·가공·연산하는 단계로, 분산·병렬 처리 기술(하둡, 스파크 등)을 활용 |
| 분석         | 처리된 데이터에서 통계, 머신러닝, 데이터마이닝 등을 활용해 의미 있는 패턴이나 인사이트를 도출하는 단계    |
| 시각화       | 분석 결과를 그래프, 차트, 대시보드 등 사람이 이해하기 쉬운 형태로 표현하는 단계                           |

**`빅데이터 수집`**

| 방법                  | 설명                                                                                                                  |
| --------------------- | --------------------------------------------------------------------------------------------------------------------- |
| 크롤링(Crawling)      | 웹 로봇(크롤러/스파이더)이 웹사이트를 자동으로 탐색하며 웹페이지, 게시물, SNS 등의 데이터를 수집하는 방법             |
| 로그 수집기           | 웹서버, 애플리케이션, 네트워크 장비 등에서 발생하는 로그 데이터를 실시간으로 수집하는 방법(예: Flume, Scribe, Chukwa) |
| 센서 네트워크         | IoT 기기·센서 등을 통해 온도, 위치, 환경 정보 등의 데이터를 실시간으로 수집하는 방법                                  |
| RSS Reader / Open API | RSS 피드나 공개된 API를 통해 뉴스, 게시물 등 웹 콘텐츠 데이터를 수집하는 방법                                         |
| ETL 프로세스          | 내부 데이터베이스, 파일 등의 데이터를 추출(Extract)·변환(Transform)·적재(Load)하여 수집하는 방법                      |

**`빅데이터 저장`**

| 방법                                         | 설명                                                                                                                                                                    |
| -------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| NoSQL                                        | 고정된 스키마 없이 Key-Value, Document, Column, Graph 등 다양한 모델로 대용량 비정형·반정형 데이터를 유연하게 저장·처리하는 데이터베이스(예: MongoDB, Cassandra, HBase) |
| 공유 데이터 시스템(Shared-data System)       | 여러 노드가 동일한 저장소를 공유하며 데이터를 처리하는 방식으로, 노드 간 데이터 일관성을 유지하기 용이함                                                                |
| 병렬 데이터베이스 관리 시스템(Parallel DBMS) | 여러 대의 서버(노드)에 데이터를 분할 저장하고 병렬로 질의를 처리해 대용량 데이터의 처리 성능을 높이는 시스템                                                            |
| 분산 파일 시스템                             | 여러 대의 서버에 파일을 나누어 분산 저장하고 하나의 파일시스템처럼 사용할 수 있도록 지원하는 시스템(예: HDFS, GFS)                                                      |
| 네트워크 저장 시스템                         | 네트워크를 통해 여러 서버가 공유 저장장치에 접근할 수 있도록 하는 시스템(예: NAS, SAN)                                                                                  |

**`빅데이터 처리`**

| 방법                                            | 설명                                                                                                                                |
| ----------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------- |
| 분산 시스템                                     | 여러 대의 독립된 컴퓨터(노드)를 네트워크로 연결해 하나의 시스템처럼 동작시켜 대용량 데이터를 처리하는 방식                          |
| 병렬 시스템                                     | 하나의 작업을 여러 개의 프로세서(또는 코어)가 동시에 나누어 처리해 처리 속도를 높이는 방식                                          |
| 분산 병렬 컴퓨팅                                | 분산 시스템과 병렬 처리를 결합해 여러 대의 노드가 작업을 나누어 동시에 병렬로 처리하는 방식                                         |
| 하둡(Hadoop)                                    | HDFS(분산 파일 시스템)와 맵리듀스를 기반으로 대용량 데이터를 분산 저장·처리하는 오픈소스 프레임워크                                 |
| 아파치 스파크(Apache Spark)                     | 인메모리(In-memory) 방식으로 데이터를 처리해 하둡 맵리듀스보다 빠른 속도로 대용량 데이터를 분산 처리하는 프레임워크                 |
| 맵리듀스(MapReduce)                             | 데이터를 여러 노드로 분산해 처리(Map)한 뒤 그 결과를 집계(Reduce)하는 분산 처리 프로그래밍 모델 / split -> map -> shuffle -> reduce |
| 복합 이벤트 처리(CEP, Complex Event Processing) | 여러 소스에서 실시간으로 발생하는 이벤트들의 패턴이나 상호관계를 분석해 의미 있는 이벤트를 즉시 탐지·처리하는 기술                  |

**`빅데이터 분석`**

| 분류                                              | 설명                                                                                                          |
| ------------------------------------------------- | ------------------------------------------------------------------------------------------------------------- |
| 탐구 요인 분석(EFA, Exploratory Factor Analysis)  | 변수들 간의 상관관계를 바탕으로 사전 가설 없이 잠재된 요인(구조)을 탐색적으로 찾아내는 분석기법               |
| 확인 요인 분석(CFA, Confirmatory Factor Analysis) | 이론이나 선행연구를 바탕으로 사전에 설정한 요인(집합)구조 모델이 실제 데이터와 부합하는지를 검증하는 분석기법 |

| 방법                     | 설명                                                                                              |
| ------------------------ | ------------------------------------------------------------------------------------------------- |
| 분류(Classification)     | 미리 정의된 범주(클래스)에 데이터를 예측·할당하는 지도학습 기반 분석기법                          |
| 군집화(Clustering)       | 데이터 간 유사도를 기준으로 비슷한 데이터끼리 그룹(군집)으로 묶는 비지도학습 기반 분석기법        |
| 머신러닝                 | 데이터로부터 스스로 패턴을 학습해 예측이나 판단을 수행하도록 하는 알고리즘 및 기법의 총칭         |
| 텍스트 마이닝            | 비정형 텍스트 데이터에서 자연어처리 기법을 활용해 의미 있는 정보나 패턴을 추출하는 기법           |
| 웹 마이닝                | 웹 페이지, 웹 구조, 웹 사용 로그 등 웹 상의 데이터를 분석해 유용한 정보를 추출하는 기법           |
| 오피니언(Opinion) 마이닝 | 텍스트에 담긴 사용자의 의견이나 평가(긍정/부정 등)를 분석해 추출하는 기법                         |
| 리얼리티 마이닝          | 휴대폰, 센서 등을 통해 수집된 위치·통화·행동 데이터를 분석해 인간관계나 행동 패턴을 파악하는 기법 |
| 소셜 네트워크 분석       | 소셜 미디어 등에서 개인·집단 간의 관계(네트워크) 구조와 연결 패턴을 분석하는 기법                 |
| 감정(Sentiment) 분석     | 텍스트에 나타난 감정이나 태도를 긍정/부정/중립 등으로 분류해 분석하는 기법                        |

### 빅데이터와 인공지능

**`머신러닝 종류`**

| 종류                         | 설명                                                                                                                    |
| ---------------------------- | ----------------------------------------------------------------------------------------------------------------------- |
| 지도(Supervised) 학습        | 입력 데이터와 정답(레이블)이 함께 주어진 학습 데이터로 입력과 출력 간의 관계를 학습하는 방식(예: 분류, 회귀)            |
| 비지도(Unsupervised) 학습    | 정답(레이블) 없이 데이터 자체의 패턴이나 구조를 학습하는 방식(예: 군집화, 차원축소, 연관규칙)                           |
| 준지도(Semi-supervised) 학습 | 소량의 레이블이 있는 데이터와 대량의 레이블 없는 데이터를 함께 활용해, 레이블링 비용을 줄이면서 학습 성능을 높이는 방식 |
| 강화(Reinforcement) 학습     | 에이전트가 환경과 상호작용하며 특정 행동에 대한 보상(reward)을 최대화하는 방향으로 정책을 학습하는 방식                 |

**`인공지능 데이터 학습의 진화`**

| 구분                                                          | 설명                                                                                                                                                     |
| ------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 전이(Transfer) 학습                                           | 특정 문제(도메인)를 학습한 모델의 지식(가중치 등)을 유사한 다른 문제에 재사용해 학습 효율을 높이는 방법                                                  |
| 전이학습 기반 사전학습(Pre-trained) 모형                      | 대규모 데이터로 미리 학습(사전학습)시킨 모델을 기반으로, 특정 목적(다운스트림 태스크)에 맞게 소량의 데이터로 추가 학습(파인튜닝)해 활용하는 방식         |
| BERT(Bidirectional Encoder Representations from Transformers) | 문장 내 단어의 좌우 문맥을 양방향(Bidirectional)으로 동시에 학습하는 트랜스포머 기반 사전학습 언어모델로, 다양한 자연어처리 태스크에 전이학습으로 활용됨 |

**`인공지능의 기술 동향`**

| 종류                                                     | 설명                                                                                                                                                                          |
| -------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| AI 프레임워크                                            | 인공지능 모델을 효율적으로 구현·학습·배포할 수 있도록 지원하는 소프트웨어 라이브러리/플랫폼(예: TensorFlow, PyTorch)                                                          |
| 생성적 적대 신경망(GAN, Generative Adversarial Networks) | 생성자(Generator)와 판별자(Discriminator) 두 신경망이 서로 경쟁하며 학습하는 생성 모델. 생성자는 실제와 유사한 가짜 데이터를 만들고, 판별자는 진짜와 가짜를 구분하도록 학습함 |
| auto-encoder                                             | 입력 데이터를 저차원(잠재공간)으로 압축(인코딩)한 뒤 원본과 유사하게 복원(디코딩)하도록 학습하는 비지도학습 기반 신경망으로, 차원축소나 이상탐지 등에 활용                    |
| 설명 가능한 인공지능(XAI, eXplainable AI)                | 인공지능 모델의 예측·판단 근거를 사람이 이해할 수 있는 형태로 설명하여 모델의 신뢰성과 투명성을 높이는 기술                                                                   |
| Auto ML                                                  | 데이터 전처리, 특성 선택, 모델 선택, 하이퍼파라미터 튜닝 등 머신러닝 모델 개발 과정을 자동화하는 기술                                                                         |
| LLM(Large Language Model)                                | 방대한 양의 텍스트 데이터로 사전학습된 대규모 언어모델로, 자연어 이해·생성 등 다양한 언어 관련 작업을 수행함                                                                  |

| ----------- | -------------------------------------------------------------------------------------------------------------------------------- |

| 사후 관리   | 비식별 정보의 활용·관리 현황을 지속적으로 점검하고, 재식별 가능성이 발견되면 즉시 처리를 중단하고 재조치하는 등 사후 관리를 수행 |

**`개인정보 비식별화 조치 방법`**

| 방법          | 설명                                                                                                                                  |
| ------------- | ------------------------------------------------------------------------------------------------------------------------------------- |
| 가명 처리     | 개인정보의 일부(이름 등 식별자)를 다른 값(가명, 코드 등)으로 대체하여 특정 개인을 알아볼 수 없도록 처리하는 기법(예: 홍길동 → 임꺽정) |
| 총계 처리     | 개인정보를 집계·합산하여 평균, 총합 등 통계값으로 변환함으로써 개별 데이터를 알 수 없도록 처리하는 기법                               |
| 데이터 삭제   | 개인을 식별할 수 있는 값(전체 또는 일부)이나 이를 유추할 수 있는 값을 삭제하는 기법                                                   |
| 데이터 범주화 | 특정 값을 범주(구간)로 묶어 대체함으로써 개인 식별을 어렵게 하는 기법(예: 나이 32세 → 30대)                                           |
| 데이터 마스킹 | 개인식별정보의 전부 또는 일부를 공백이나 특수문자(\*) 등으로 대체하여 보이지 않도록 처리하는 기법(예: 홍길동 → 홍\*\*)                |

## 분석 방안 수립

### 데이터 분석

부서 단위로 관리되는 일차원적인 데이터 분석은 지양한다. 이는 전체 비즈니스 관점의 역할을 기대하기 어렵다.

전략 도출을 위해 가치기반 데이터 분석을 지향한다.

데이터 분석은 규모가 아니라 어떤 시각과 통찰을 얻을 수 있는가의 문제다.

### 데이터 분석 기획

**`목표 시점에 따른 분류`**

| 방식                                 | 설명                                                                                                                                   |
| ------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------- |
| 단기적 접근 방식(과제 중심적 접근)   | 당면한 문제를 빠르게 해결하기 위해 시급성이 높은 분석 과제를 우선 선정해 Quick Win 형태로 신속하게 수행하는 방식                       |
| 중장기적 접근 방식(마스터 플랜 접근) | 전략적 중요도에 따라 전사 차원의 분석 마스터플랜을 수립하고, 장기적 관점에서 지속적으로 분석 체계를 개선해 나가는 방식                 |
| 혼합 방식(분석 기획시)               | 전사 차원의 마스터플랜을 수립하되, 그 안에서 우선순위가 높은 과제는 단기적으로 먼저 추진하는 방식으로, 실제 분석 기획 시 권장되는 방식 |

**`분석 기획 필요역량`**

| 역량              | 설명                                                                                                     |
| ----------------- | -------------------------------------------------------------------------------------------------------- |
| Math & Statistics | 통계적 기법과 분석 방법론에 대한 지식을 바탕으로 데이터를 정량적으로 분석하는 역량                       |
| IT                | 프로그래밍, 데이터베이스 등 데이터를 수집·처리·구현할 수 있는 기술적 역량                                |
| Domain Knowledge  | 해당 산업·업무 영역에 대한 이해를 바탕으로 문제를 정의하고 분석 결과를 비즈니스 인사이트로 해석하는 역량 |

**`데이터 분석 유형`**

| 유형                    | 설명                                                                     |
| ----------------------- | ------------------------------------------------------------------------ |
| 설명(Descriptive) 분석  | 과거에 어떤 일이 발생했는지를 파악하는 분석(현황 파악, 기술통계 등)      |
| 예측(Predictive) 분석   | 과거 데이터를 바탕으로 미래에 어떤 일이 일어날지를 예측하는 분석         |
| 진단(Diagnostic) 분석   | 특정 현상이나 결과가 왜 발생했는지 그 원인을 파악하는 분석               |
| 처방(Prescriptive) 분석 | 예측된 결과에 대해 어떤 행동을 취해야 하는지 최적의 대안을 제시하는 분석 |

| 전략적 중요도 | 전략적 필요성, 시급성    |

| PoC(Proof of Concept)          | 새로운 기술이나 분석 방법론을 본격적으로 도입하기 전, 실제 적용 가능성을 사전에 검증하는 데 활용 | 소규모로 개념 검증을 수행해 기술적 실현 가능성과 효과를 미리 확인하는 절차         |

### 분석 로드맵 설정

**마스터 플랜에서 정의한 목표** 를 기반으로 분석 과제를 수행하기 위해 필요한 기준 등을 담아 종합적인 계획을 만든다.

**`분석 로드맵 수립 절차`**

| 절차                       | 설명                                                                                                                                              |
| -------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------- |
| 데이터 분석 체계 도입      | 분석 과제를 정의하고 데이터 분석 마스터플랜을 수립하여, 조직 내 분석 요건을 도출하고 분석 시스템(환경)을 도입·구축하는 단계                       |
| 데이터 분석 유효성 검증    | 도입된 분석 체계를 바탕으로 파일럿(시범) 과제를 수행해 정확성과 실효성을 검증하고, 유효성이 확인된 분석 모델을 정식 운영 프로세스에 적용하는 단계 |
| 데이터 분석 확산 및 고도화 | 검증된 분석 모델과 프로세스를 조직 전체로 확산·내재화하고, 지속적인 개선을 통해 분석 수준을 고도화하는 단계                                       |

**`분석 로드맵 세부 일정 계획`**

데이터 수집 및 확보와 데이터 준비 단계는 순차적으로 진행한다.

모델링 단계는 반복적으로 수행한다.

### 분석 문제 정의

**`분석 과제 도출 방법`**

| 방법             | 단계                | 설명                                                                                                                                   |
| ---------------- | ------------------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| 상향식 접근 방식 | 발산(Diverge) 단계  | 문제 정의 자체가 어려운 경우 데이터를 탐색적으로 분석(비지도학습 등)해 다양한 가설과 아이디어를 도출하며 문제를 발굴하는 방식          |
| 하향식 접근 방식 | 수렴(Converge) 단계 | 이미 인지한 문제를 문제 탐색→정의→해결방안 탐색→타당성 검토 단계를 거쳐 데이터 분석 문제로 구체화하고 여러 대안을 하나로 좁혀가는 방식 |

### 하향식 접근 방식(Top Down Approach)

**`하향식 접근 방식 구성`**

| 단계                     | 구분                                                          | 설명                                                                                                                                |
| ------------------------ | ------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------- |
| 문제 탐색(Discovery)     | 비즈니스 모델 기반, 외부 참조 모델 기반, 분석 유스케이스 정의 | 비즈니스 모델 캔버스나 유사 업계 벤치마킹, 유스케이스 정의 등을 통해 분석 기회가 될 수 있는 다양한 문제 후보를 폭넓게 발굴하는 단계 |
| 문제 정의(Definition)    | 비즈니스 문제, 분석 문제                                      | 발굴한 비즈니스 문제를 데이터 분석 관점에서 재정의하여, 어떤 데이터와 분석 방법을 사용할지 명확히 하는 단계                         |
| 해결방안 탐색(Solution)  |                                                               | 정의된 분석 문제를 해결하는 데 필요한 데이터, 분석 기법, 분석 시스템 등을 탐색하고 대안을 도출하는 단계                             |
| 타당성 평가(Feasibility) | 경제적 타당성, 데이터 및 기술적 타당성                        | 도출된 대안에 대해 비용 대비 효과(경제적 타당성)와 데이터 확보 가능성·기술적 구현 가능성을 평가해 최종 대안을 선정하는 단계         |

**`비즈니스 모델 캔버스를 활용한 과제 발굴`**

| 단위 및 영역     | 설명                                                                              |
| ---------------- | --------------------------------------------------------------------------------- |
| 업무 단위        | 생산, 운영 등 실제 업무 프로세스가 발생하는 영역에서 분석 기회를 발굴하는 단위    |
| 제품 단위        | 제품이나 서비스 자체를 개선·혁신할 수 있는 관점에서 분석 기회를 발굴하는 단위     |
| 고객 단위        | 고객 채널, 관계, 세그먼트 등 고객 관점에서 분석 기회를 발굴하는 단위              |
| 규제와 감사 영역 | 법적 규제 준수, 내부 감사 대응 등 컴플라이언스 관점에서 분석 기회를 발굴하는 영역 |
| 지원 인프라 영역 | 인적자원, IT 등 비즈니스를 지원하는 인프라 관점에서 분석 기회를 발굴하는 영역     |

**`분석 기회 발굴의 범위 확장`**

| 관점                  | 영역                           | 설명                                                                                          |
| --------------------- | ------------------------------ | --------------------------------------------------------------------------------------------- |
| 거시적 관점           | 사회, 기술, 경제, 환경, 정치   | 사회·기술·경제·환경·정치(STEEP) 등 외부의 거시적 환경 변화를 살펴 분석 기회를 탐색하는 관점   |
| 경쟁자 확대 관점      | 대체제, 경쟁자, 신규 진입자    | 대체재, 기존 경쟁자, 신규 진입자 등 산업 내 경쟁 구도의 변화를 살펴 분석 기회를 탐색하는 관점 |
| 시장의 니즈 탐색 관점 | 고객, 채널, 영향자(Influencer) | 고객, 유통 채널, 영향자(Influencer) 등 시장의 니즈 변화를 관찰해 분석 기회를 탐색하는 관점    |
| 역량의 재해석 관점    | 내부 역량, 파트너와 네트워크   | 자사가 보유한 내부 역량과 파트너·네트워크를 새롭게 해석해 분석 기회를 탐색하는 관점           |

### 상향식 접근 방식(Bottom Up Approach)

기존 하향식 접근 방식의 한계를 극복하기 위해 등장.

- 새로운 문제 탐색에 대한 한계 및 다양한 환경에서 발생한 문제에 대한 해결책으로는 부적합.

**`전통적 사고 극복방안`**

| 극복방안                    | 특징                                                                                                                                                                          |
| --------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 디자인 사고 접근법          | 현장(사용자) 관찰과 공감을 통해 다양한 가설을 도출하고, 시행착오를 거치며 문제를 지속적으로 구체화·개선해 나가는 발산적 사고 방식                                             |
| 비지도학습 방법에 의한 수행 | 목적(정답)이 정해지지 않은 상태에서 데이터 자체의 유사성을 기준으로 군집화 등 비지도학습 기법을 적용해 데이터를 그룹화하고, 그 결과에서 새로운 인사이트(문제)를 발견하는 방법 |
| 빅데이터 환경에서의 분석    | 다양하고 방대한 데이터를 탐색적으로 분석해, 기존에 인지하지 못했던 새로운 문제를 데이터 기반으로 재정의하고 발견하는 방식. 인과관계에서 상관관계 분석으로 이동                |

**`프로토타이핑 - 상향식 접근 방식의 문제 해결 방법`**

| 구분   | 설명                                                                                                                                                                     |
| ------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 방법   | 분석의 결과물을 신속하게 미리 만들어 이해관계자에게 제시하고 피드백을 받아 반복적으로 개선해 나가는 시행착오(Trial and Error) 기반의 문제 해결 방법                      |
| 필요성 | 사용자가 원하는 바를 사전에 정확히 정의하기 어렵고, 데이터의 존재 여부나 품질이 분석 전에 충분히 검증되지 않은 상황에서는 미리 시도해보고 결과를 확인할 필요가 있기 때문 |
| 특징   | 문제를 명확히 정의하기 어려운 경우에도 일단 분석을 시도한 뒤 그 결과를 검토하며 문제와 해법을 점진적으로 구체화해 나가는 상향식·반복적 접근이 가능함                     |
| 구성   | 가설 생성(Hypothesis) → 디자인에 대한 실험(Design Experiments) → 실제 환경에서의 테스트(Test) → 통찰 도출(Insight)이 순환적으로 반복되는 과정으로 구성됨                 |

### 데이터 분석 방법론

**`구성 요건`**

| 구성                                | 설명                                                                                   |
| ----------------------------------- | -------------------------------------------------------------------------------------- |
| 상세한 절차(Procedures)             | 각 단계에서 무엇을 어떤 순서로 수행해야 하는지 구체적으로 정의된 활동들의 집합         |
| 방법(Methods)                       | 절차 내 각 활동을 수행하기 위한 구체적인 방식과 접근법                                 |
| 도구와 기법(Tools & Techniques)     | 절차와 방법을 실제로 수행하는 데 활용되는 소프트웨어, 분석 기법 등                     |
| 템플릿과 산출물(Template & Outputs) | 각 단계를 수행한 결과를 정리하는 문서 양식과 그에 따른 산출물                          |
| 활용 가능한 수준의 난이도           | 실무자가 실제 프로젝트에 바로 적용할 수 있을 만큼 적정한 구체성과 난이도를 갖추어야 함 |

**`생성 과정`**

| 과정   | 설명                                                                                  |
| ------ | ------------------------------------------------------------------------------------- |
| 형식화 | 여러 사람의 경험과 지식을 정리해 초기 방법론(절차, 방법 등)의 형태를 만드는 과정      |
| 체계화 | 형식화된 내용을 일관된 원칙과 기준에 따라 순서와 체계를 갖춘 방법론으로 정리하는 과정 |
| 내재화 | 체계화된 방법론을 실제 프로젝트에 반복적으로 적용해 조직 내에 뿌리내리도록 하는 과정  |

**`계층적 프로세스 모델 구성`**

| 구성         | 설명                                                                                                                                         |
| ------------ | -------------------------------------------------------------------------------------------------------------------------------------------- |
| 단계(Phase)  | 프로세스 그룹을 통해 완성된 단계별 산출물을 생성하는 단위로, 완료 기준(Exit Criteria)에 따라 다음 단계로 넘어가는 기준선(Baseline) 역할을 함 |
| 테스크(Task) | 단계를 구성하는 단위 활동으로, 물리적 또는 논리적 단위로 품질 검토를 진행할 수 있는 단위 프로세스                                            |
| 스탭(Step)   | 입력 자료(Input)에 특정 기법(Techniques)을 적용하고 세부 절차를 따라 산출물(Output)을 만들어내는 최소 단위 프로세스                          |

### KDD(Knowledge Discovery in Database) 분석 방법론

**`분석 절차 5단계`**

| 절차          | 설명                                                                                                 |
| ------------- | ---------------------------------------------------------------------------------------------------- |
| 데이터셋 선택 | 분석 목적에 맞게 원본 데이터에서 필요한 데이터셋을 선택하고 생성하는 단계                            |
| 데이터 전처리 | 선택된 데이터에서 잡음, 이상값, 결측치 등을 제거·보정하는 단계                                       |
| 데이터 변환   | 전처리된 데이터를 마이닝 알고리즘에 적용 가능한 형태로 변환하고 필요한 변수를 축소·생성하는 단계     |
| 데이터 마이닝 | 변환된 데이터에 분류, 군집화, 예측 등의 기법을 적용해 숨겨진 패턴이나 규칙을 찾는 단계               |
| 결과 평가     | 데이터 마이닝 결과를 해석·평가하여 지식(Knowledge)으로 활용하고, 필요 시 이전 단계로 피드백하는 단계 |

### CRISP-DM(Cross Industry Standard Process for Data Mining) 분석 방법론

**`CRISP-DM 4계층`**

| 계층                             | 설명                                                                                                     |
| -------------------------------- | -------------------------------------------------------------------------------------------------------- |
| 단계(Phases)                     | 여러 개의 일반화 태스크로 구성된 최상위 레벨로, 업무 이해·데이터 이해 등 6단계 프로세스의 큰 틀을 의미함 |
| 일반화 태스크(Generic Tasks)     | 데이터 마이닝의 단일 프로세스를 포괄적이고 안정적으로 설명하기 위해 범용적으로 정의한 단위 작업          |
| 세분화 테스크(Specialized Tasks) | 일반화 태스크를 특정 상황이나 프로젝트 특성에 맞게 구체적인 방식으로 기술한 것                           |
| 프로세스 실행(Process Instances) | 실제 데이터 마이닝을 수행하는 과정에서 발생한 활동, 결정, 결과를 구체적으로 기록한 것                    |

**`분석 절차 6단계`**

| 절차        | 설명                                                                                                 |
| ----------- | ---------------------------------------------------------------------------------------------------- |
| 업무 이해   | 비즈니스 목표와 요구사항을 파악하고 이를 데이터 마이닝 문제로 정의하는 단계                          |
| 데이터 이해 | 초기 데이터를 수집해 데이터의 품질을 파악하고 숨겨진 정보를 탐색하는 단계                            |
| 데이터 준비 | 분석에 사용할 데이터셋을 선택·정제·통합·포맷팅하는 단계로, 전체 프로젝트에서 가장 많은 시간이 소요됨 |
| 모델링      | 다양한 모델링 기법과 알고리즘을 선택해 최적의 파라미터로 모델을 구축하는 단계                        |
| 평가        | 구축된 모델이 비즈니스 목표에 부합하는지, 진행 과정에서 누락되거나 잘못된 점은 없는지 평가하는 단계  |
| 전개        | 완성된 모델을 실제 업무에 적용하고 모니터링·유지보수 계획을 수립하는 단계                            |

### SEMMA(Sample, Explore, Modify, Model and Assess) 분석 방법론

**`분석 절차 5단계`**

| 절차   | 설명                                                                                                                     |
| ------ | ------------------------------------------------------------------------------------------------------------------------ |
| 추출   | 전체 데이터 중 통계적으로 유의미한 표본 데이터를 추출(Sample)하는 단계                                                   |
| 탐색   | 추출된 데이터의 특성과 변수 간의 관계를 통계 기법이나 시각화로 탐색(Explore)하는 단계                                    |
| 수정   | 탐색 결과를 바탕으로 변수를 선택·변환·생성하고 결측치·이상치를 처리해 모델링에 적합하도록 데이터를 가공(Modify)하는 단계 |
| 모델링 | 목표 변수를 설명하거나 예측할 수 있는 다양한 기법을 적용해 모형을 구축(Model)하는 단계                                   |
| 평가   | 구축된 모델의 유용성과 신뢰성, 정확도 등을 평가·검증(Assess)하는 단계                                                    |

### 빅데이터 분석 방법론 개발 절차

**`1. 분석 기획(Planning)`**

| Task                       | 설명                                                                                  |
| -------------------------- | ------------------------------------------------------------------------------------- |
| 비즈니스 이해 및 범위 설정 | 비즈니스 도메인과 목표를 이해하고, 프로젝트의 범위를 명확히 설정하는 태스크           |
| 프로젝트 정의 및 계획 수립 | 정의된 문제를 바탕으로 프로젝트의 목표와 추진 계획(일정, 자원 등)을 구체화하는 태스크 |
| 프로젝트 위험 계획 수립    | 프로젝트 진행 중 발생할 수 있는 위험 요소를 식별하고 대응 방안을 수립하는 태스크      |

**`2. 데이터 준비(Preparing)`**

| Task                       | 설명                                                                         |
| -------------------------- | ---------------------------------------------------------------------------- |
| 필요 데이터 정의           | 분석 목적에 맞게 필요한 데이터의 종류와 범위를 정의하는 태스크               |
| 데이터 스토어 설계         | 정의된 데이터를 저장·관리할 데이터 스토어(저장소)의 구조를 설계하는 태스크   |
| 데이터 수집 및 정합성 점검 | 필요한 데이터를 내·외부에서 수집하고 데이터의 정합성(품질)을 점검하는 태스크 |

**`3. 데이터 분석(Analyzing)`**

| Task               | 설명                                                                         |
| ------------------ | ---------------------------------------------------------------------------- |
| 분석용 데이터 준비 | 분석에 활용할 수 있도록 데이터를 정제·가공하여 준비하는 태스크               |
| 텍스트 분석        | 비정형 텍스트 데이터를 대상으로 분석을 수행하는 태스크                       |
| 탐색적 분석        | 데이터의 특성과 변수 간의 관계를 통계 기법이나 시각화로 탐색하는 태스크(EDA) |
| 모델링             | 분석 목적에 맞는 알고리즘을 선정하고 모형을 구축하는 태스크                  |
| 모델 평가 및 검증  | 구축된 모델의 성능과 타당성을 평가·검증하는 태스크                           |

**`4. 시스템 구현(Developing)`**

| Task                  | 설명                                                                              |
| --------------------- | --------------------------------------------------------------------------------- |
| 설계 및 구현          | 검증된 분석 모델을 실제 운영환경에 반영할 수 있도록 시스템을 설계·구현하는 태스크 |
| 시스템 테스트 및 운영 | 구현된 시스템을 테스트하여 안정성을 확인하고 실제 운영에 적용하는 태스크          |

**`5. 평가 및 전개(Deploying)`**

| Task                  | 설명                                                                                        |
| --------------------- | ------------------------------------------------------------------------------------------- |
| 모델 발전계획 수립    | 운영 중인 모델의 성능을 지속적으로 모니터링하고 개선·고도화하기 위한 계획을 수립하는 태스크 |
| 프로젝트 평가 및 보고 | 프로젝트 전체의 성과를 평가하고 그 결과를 이해관계자에게 보고하는 태스크                    |

### 데이터 분석 거버넌스

데이터 분석 업무를 하나의 기업 문화로 정착하고, 이를 지속적으로 고도화한다.

**`데이터 분석 거버넌스 구성요소`**

| 요소                                          | 설명                                                                                          |
| --------------------------------------------- | --------------------------------------------------------------------------------------------- |
| 조직(Organization)                            | 분석 기획·수행·관리를 담당하는 조직구조와 역할·책임을 정의하는 요소                           |
| 운영 프로세스(Process)                        | 분석 과제의 기획부터 운영까지 이어지는 일련의 업무 절차와 체계를 정의하는 요소                |
| 지원 인프라(System)                           | 데이터 분석에 필요한 시스템, 소프트웨어, 하드웨어 등 기술적 인프라를 지원하는 요소            |
| 거버넌스(Data)                                | 데이터의 표준화, 품질관리, 활용 원칙 등 데이터 자체를 체계적으로 관리하기 위한 요소           |
| 분석 교육 및 마인드 육성 체계(Human Resource) | 조직 구성원의 분석 역량을 향상시키고 데이터 기반 의사결정 문화를 조성하기 위한 교육·양성 체계 |

### 데이터 거버넌스

데이터 표준화 및 관리체계 수립을 위한 프레임워크와 저장소를 구축한다.

**`데이터 거버넌스 주요 관리 대상`**

| 요소                         | 설명                                                                                                                    |
| ---------------------------- | ----------------------------------------------------------------------------------------------------------------------- |
| 마스터 데이터(Master Data)   | 여러 시스템·부서에서 공통으로 사용하는 핵심 기준 정보(고객, 상품 등)로, 조직 내 데이터 일관성 유지의 기준이 되는 데이터 |
| 메타 데이터(Meta Data)       | 데이터에 대한 데이터로, 데이터의 구조·형식·의미·이력 등을 설명하는 정보                                                 |
| 데이터 사전(Data Dictionary) | 데이터 항목의 명칭, 정의, 형식, 규칙 등을 체계적으로 정리해 놓은 참조 문서                                              |

**`데이터 거버넌스 구성 요소`**

| 요소               | 설명                                                                                       |
| ------------------ | ------------------------------------------------------------------------------------------ |
| 원칙(Principle)    | 데이터를 안전하고 일관되게 관리하기 위한 표준, 정책, 보안 등의 기준과 지침을 수립하는 요소 |
| 조직(Organization) | 데이터 거버넌스를 관리·운영할 조직 및 담당자의 역할과 책임을 정의하는 요소                 |
| 프로세스(Process)  | 데이터 관리를 위한 체계적인 절차와 작업 활동(수집, 저장, 품질관리 등)을 정의하는 요소      |

### 데이터 분석 수준진단

**`분석 준비도(Readiness) 6가지 영역`**

| 영역           | 설명                                                                                                         |
| -------------- | ------------------------------------------------------------------------------------------------------------ |
| 분석 업무 파악 | 발생한 사실 분석, 예측 분석, 시뮬레이션, 최적화 분석 등 현재 수행 중인 분석 업무·과제를 파악하고 있는지 진단 |
| 인력 및 조직   | 분석 전문 인력의 보유 여부, 관련 조직의 존재 여부, 경영진의 분석에 대한 의지와 마인드를 진단                 |
| 분석 기법      | 업무에 적합한 분석 기법·알고리즘을 활용하고 있는지, 이를 지원하는 기법 라이브러리를 보유하고 있는지 진단     |
| 분석 데이터    | 분석 업무 수행에 필요한 내·외부 데이터를 확보하고 접근·활용할 수 있는지 진단                                 |
| 분석 문화      | 사실(데이터)에 근거해 의사결정을 내리는 조직 문화와 데이터 공유·협업 문화가 존재하는지 진단                  |
| IT 인프라      | 분석에 필요한 하드웨어·소프트웨어 등 시스템을 보유하고 있으며, 필요 시 자원을 확충할 수 있는지 진단          |

**`분석 성숙도(Maturity) 모델`**

| 구분 | 설명                                                                  |
| ---- | --------------------------------------------------------------------- |
| 특징 | 비즈니스 부문, 조직 및 역량 부문, IT 부문 총 3개 부문을 대상으로 실시 |
| 단계 | 성숙도 수준에 따라 도입, 활용, 확산, 최적화 단계로 구분               |

| 단계   | 설명                                                                             |
| ------ | -------------------------------------------------------------------------------- |
| 도입   | 일부 부서에서 분석을 시범적으로 시작하는 단계                                    |
| 활용   | 분석 결과를 실제 업무에 반복적으로 적용해 활용하기 시작하는 단계                 |
| 확산   | 전사 차원에서 분석이 체계적으로 관리되며 조직 전반으로 확산되는 단계             |
| 최적화 | 분석이 경영 전략과 업무 전반에 내재화되어 지속적으로 성과를 창출·고도화하는 단계 |
