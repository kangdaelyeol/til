## 빅데이터 개요 및 활용

### 데이터 특징

단순한 객체로도 가치가 있으며, 다른 객체와의 상호관계 속에서 더 큰 가치를 갖는다.

**`데이터의 존재적 / 당위적 특성`**

| 특성        | 특징                               |
| ----------- | ---------------------------------- |
| 존재적 특성 | 객관적 사실                        |
| 당위적 특성 | 추론, 추정, 예측, 전망을 위한 근거 |

### 정량적 / 정성적 데이터

|      | 정량적 데이터(Quantitative Data)                     | 정성적 데이터(Qualitative Data)                                       |
| ---- | ---------------------------------------------------- | --------------------------------------------------------------------- |
| 유형 | 수치, 도형, 기호 등으로 표현되는 데이터              | 언어, 문자 등으로 표현되는 데이터                                     |
| 특징 | 정형화된 값으로 고정된 필드에 저장되어 형식이 일정함 | 정형화되지 않아 형태와 구조가 다양하고 저장·분석에 많은 비용이 발생함 |
| 관점 | 객관적                                               | 주관적                                                                |
| 구성 | 규칙적이고 연속적인 구조                             | 불규칙적인 구조                                                       |
| 형태 | 수치, 숫자, 통계자료                                 | 텍스트, 이미지, 영상, 음성 등                                         |
| 위치 | RDB, 스프레드시트 등 고정된 필드에 저장              | 데이터 자체가 콘텐츠(값)로 저장되어 필드 구분이 없음                  |
| 분석 | 통계 분석                                            | 텍스트마이닝, 감성분석 등 별도 분석기법 필요                          |

### 정형 / 반정형 / 비정형 데이터

|      | 정형 데이터(Structured Data)                                                       | 반정형 데이터(Semi-Structured Data)                                                                                                     | 비정형 데이터(Unstructured Data)                                           |
| ---- | ---------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------- |
| 설명 | 미리 정의된 스키마(고정된 필드)에 따라 저장되는 데이터. 예) RDB, 스프레드시트, CSV | 데이터 내부에 구조(스키마)를 설명하는 메타데이터를 포함하지만 고정된 필드 형태로 저장되지는 않는 데이터. 예) XML, JSON, HTML, 로그 파일 | 정해진 구조(스키마) 없이 저장되는 데이터. 예) 텍스트, 이미지, 음성, 영상   |
| 특징 | 연산 가능하며 정해진 형식과 규칙에 따라 저장·검색·분석이 용이함                    | 연산은 불가능하지만 태그·마크업 등을 파싱하면 구조를 유추할 수 있음                                                                     | 연산 불가능하며 텍스트마이닝, 음성인식, 영상분석 등 별도 분석기법이 필요함 |

### 가역 / 불가역 데이터

|                | 가역 데이터                                                           | 불가역 데이터                                                 |
| -------------- | --------------------------------------------------------------------- | ------------------------------------------------------------- |
| 설명           | 별도의 키나 매핑정보를 이용해 원래 상태로 복원(환원)할 수 있는 데이터 | 한 번 처리되면 원래 상태로 복원이 불가능한 데이터             |
| 환원성(추적성) | 있음 - 키·매핑테이블을 통해 원본 복원 및 추적 가능                    | 없음 - 원본 복원 및 개인 식별 불가능                          |
| 의존성         | 원본 데이터 또는 별도의 키(매핑정보)에 의존적                         | 원본 데이터와 독립적                                          |
| 원본과의 관계  | 원본과의 대응(매핑) 관계가 유지됨                                     | 원본과의 연결고리가 완전히 제거됨                             |
| 처리과정       | 가명처리(치환, 암호화 등)                                             | 총계처리, 삭제, 범주화, 마스킹 등 완전 익명처리               |
| 활용분야       | 통계작성, 연구 등 목적 내 제한적 활용                                 | 개인정보보호법 적용 대상에서 제외되어 자유로운 활용·공개 가능 |

### OLTP / OLAP

| 구분               | OLTP(OnLine Transaction Processing)                                                | OLAP(OnLine Analytical Processing)                                             |
| ------------------ | ---------------------------------------------------------------------------------- | ------------------------------------------------------------------------------ |
| 설명               | 은행, 예약, ERP 등 업무 시스템에서 발생하는 짧고 단순한 트랜잭션을 실시간으로 처리 | 다양한 관점에서 데이터를 다차원적으로 분석하여 의사결정을 지원                 |
| 데이터 구조        | 정규화된 관계형 구조(중복 최소화, 데이터 무결성 중시)                              | 다차원(Cube) 구조, 스타/스노우플레이크 스키마 등 분석에 최적화된 비정규화 구조 |
| 데이터 갱신        | Insert/Update/Delete가 실시간·빈번하게 발생                                        | 정기적(배치)으로 대량 적재, 갱신은 드묾(Read 중심)                             |
| 응답 시간          | 매우 짧음(수 밀리초 단위, 즉각적 처리 요구)                                        | 상대적으로 김(복잡한 집계 연산으로 수 초~수 분)                                |
| 데이터 범위        | 현재 시점의 최신 데이터 위주                                                       | 과거부터 현재까지의 이력(누적) 데이터                                          |
| 데이터 성격        | 운영 데이터(원시 트랜잭션 데이터)                                                  | 분석용 요약·집계 데이터                                                        |
| 데이터 크기        | 트랜잭션 단위로 상대적으로 작음                                                    | 여러 트랜잭션이 누적되어 대용량                                                |
| 데이터 내용        | 최신의 상세(원자 단위) 데이터                                                      | 요약·집계된 다차원 데이터                                                      |
| 데이터 특성        | 동적(수시로 변경됨)                                                                | 정적(한번 적재되면 잘 변경되지 않음)                                           |
| 데이터 엑세스 빈도 | 짧고 단순한 질의가 매우 빈번하게 발생                                              | 복잡한 질의가 상대적으로 드물게 발생                                           |
| 질의 결과 예측     | 사전에 정의된 단순 질의로 결과 예측 가능                                           | 사용자마다 질의가 다양(Ad-hoc)하여 결과 예측이 어려움                          |

### 데이터 웨어하우스(Data Warehouse, DW)

데이터만이 아닌 분석 방법까지도 포함하여 조직 내 의사결정을 지원하는 정보 관리 시스템.

**`DW 특징`**

| 특징                            | 설명                                                                                           |
| ------------------------------- | ---------------------------------------------------------------------------------------------- |
| 주제지향성(Subject-orientation) | 특정 업무(애플리케이션) 단위가 아닌 고객, 상품 등 특정 주제 중심으로 데이터를 구성             |
| 통합성(Integration)             | 여러 운영시스템(원천 데이터)에서 수집한 데이터를 일관된 형식·명명규칙·코드체계로 통합하여 저장 |
| 시계열성(Time-variant)          | 특정 시점의 스냅샷이 아닌 시간의 흐름에 따라 변화하는 데이터를 축적하여 이력을 관리            |
| 비휘발성(Non-volatilization)    | 한 번 적재된 데이터는 삭제·변경되지 않고 읽기(Read) 전용으로 유지됨                            |

**`DW 구성 요소`**

| 구성 요소                     | 설명                                                                                   |
| ----------------------------- | -------------------------------------------------------------------------------------- |
| 데이터 모델(Data Model)       | 데이터를 저장하는 논리적 구조(스타 스키마, 스노우플레이크 스키마 등 다차원 모델링)     |
| ETL(Extract, Transform, Load) | 원천 데이터를 추출(Extract)·변환(Transform)·적재(Load)하여 DW로 옮기는 과정            |
| ODS(Operational Data Store)   | 운영 데이터를 원본과 유사한 형태로 통합 저장해 DW 적재 전 중간 저장소 역할을 하는 영역 |
| Metadata                      | 데이터에 대한 데이터로, 데이터의 구조·의미·출처·변경이력 등을 관리해 DW 활용을 지원    |
| OLAP                          | 적재된 데이터를 다차원적으로 분석하여 사용자의 의사결정을 지원하는 분석 도구/기법      |
| Data Mining                   | 대용량 데이터에서 통계·기계학습 기법으로 숨겨진 패턴이나 규칙을 발견하는 기법          |
| 분석 도구                     | 리포팅, 시각화, 대시보드 등 사용자가 데이터를 조회·분석할 수 있도록 지원하는 도구      |
| 경영기반 솔루션               | DW의 데이터를 경영 전략(BI, CRM, SCM 등) 수립에 활용할 수 있도록 지원하는 응용 솔루션  |
