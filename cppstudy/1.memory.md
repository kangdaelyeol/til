## Variable

### 변수 크기

int 자료형의 사이즈는 컴파일러 또는 아키텍처마다 다를 수 있다(최소 2바이트).

환경 독립적으로 자료형을 고정된 크기로 사용하기 위해서 `<cstdint>` 헤더에 정의된 자료형을 사용한다.

```cpp
  #include<cstdint>

  // static_assert로 자료형 사이즈 체크
  static_assert(sizeof(int) == 4)

  // cstdint 헤더에 정의된 고정된 자료형 사용
  uint64_t ut = 10;
```

### 구조체 - Memory Access Pattern

변수를 할당하는 위치 및 방법은 실행 환경마다 다르다.

구조체 같은 경우, 맴버 변수의 각 자료형이 다르기 때문에 다양한 크기의 구조체가 존재한다.

구조체의 크기는 반드시 해당 구조체 안에 변수 중 가장 큰 자료형의 크기로 나누었을때 떨어지는 크기여야 한다,

- 메모리 관리법에 따라 구조체의 크기는 맴버중 가장 큰 자료형의 크기의 배수가 되어야 하므로, 이를 보정하기 위해 메모리 공간 사이에 padding을 넣어준다.

```cpp
  struct st1{
    char a; // 1
    int b; // 4
    double c; // 8
  };
  struct st1 s1; // 16 bytes char(0) padding(1-3) int(4-7) double(8-15)

  struct st2{
    char a; // 1
    double c; // 8
    int b; // 4
  };
  struct st2 s2; // 24 bytes char(0) double(8-15) int(16-19) padding(20-23)
```

## Stack / Heap

### Function call - Stack frame

stack은 function call이 발생할 때마다 그 함수안에서 얼마나 메모리가 할당되어야 하는지 컴파일 과정에서 미리 계산된 후 stack에 정해진 크기만큼 할당된다. 이러한 할당 단위를 stack frame 이라고 한다.

stack frame의 구성은 다음과 같다.

- Next Instructor Address
- Return Address
- arguments
- member variable(This / class function call과 같은 경우에만 있음)
- Variables

각 구성요소 값이 할당되는 물리적 위치는 프로세서, 컴파일러, 아키텍처마다 다르다.

변수의 할당 방식도 상위 주소에서 하위 주소값으로 Stack형으로 쌓아가듯이 선언하지만, 이 또한 컴파일러, 아키택처 스타일에 의존한다.

### Heap의 장점

| 장점               | 설명                                                                                                                                                                                                                                                                         |
| ------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Dynamic allocation | 컴파일 환경에서 얼마나 할당되어야 할지 모르는 경우 런타임 환경에서 동적으로 메모리를 할당할 수 있다                                                                                                                                                                          |
| Life cycle         | stack에서 어떠한 function call을 통해 저장해둔 변수 값이 있는데 stack frame이 반환 되면서 그 정보가 사라지는 life cycle문제가 발생할 수 있다. 이 경우 Heap에 그 데이터를 저장해두고 stack상에서는 pointer만 관리해 stack frame간의 포인터를 넘겨주어 데이터를 관리할 수 있다 |
| Large size         | stack은 크기 할당에 한계가 있기 때문에 일반적으로 큰 변수를 stack에 할당하는 것은 효율적이지 않다. 그래서 일반적으로 큰 데이터(1MB 언저리 넘어가는 array할당)를 관리할 때는 Heap을 사용해야 한다                                                                             |

### Heap Memory 관리 스타일

**`C Style - malloc / free`**

stdlib 헤더파일에서 제공하는 malloc / free 메서드를 사용하는 방식.

c++에서 특정한 자료형(class)에 대해서 Heap에 직접 할당하는 경우, class의 생성자와 소멸자가 호출되지 않는 현상이 있어 권장하지 않는 방식이다.

```c
  #include<stdlib.h>
  int *ptr = (int*)malloc(sizeof(int) * 5);
  free(ptr);

```

**`C++ Style - new / delete`**

C++ 문법 추가된 new / delete 키워드를 사용하여 할당하는 방식.

메모리 헤제를 직접 해야 하기 때문에 완벽하게 안전하지 않다. 따라서 memory leak 현상이 발생 할 가능성이 있음.

```cpp
  int *ptr = new int[5];
  Cat *catp = new Cat[5]; // Cat class의 생성자 실행

  delete [] ptr;
  delete [] catp; // Cat class의 소멸자 실행
```

**`Safer C++ Style - Smart_ptr / Vector`**

```cpp
 #include<memory>

 std::unique_ptr<Cat> catp = std::make_unique<Cat>(...args) // unique_ptr - make_unique
 vector<int> int_vec(5); // size -> 5
 // 이 두가지 경우도 heap에 메모리를 할당해서 관리를 하는데, 소멸자가 알아서 호출되어 대부분 memory leak 현상을 방지할 수 있다.
```

### Stack vs Heap

- Heap 메모리 할당은 Stack 메모리 할당보다 느리다
  - 메모리 할당 크기를 런타임 환경에서 결정하기 때문
  - Multi threads programming시 여러 개의 쓰레드를 다루는데, 각 쓰레드마다 힙에 대한 접근 권한을 가지게 된다. 이때 Race condition을 없애기 위해 복잡한 방식을 통한 allocation / disallocation과정을 거치게 된다.
- 따라서 상황에 맞춰서 Heap할당이 필요한 경우 Stack할당이 필요한 경우를 가려낼 수 있어야 한다.

```cpp
  int *ap = new int;
	int *ap1 = new int;
	int *ap2 = new int;
	cout << ap << endl; //0x148e06c60
	cout << ap1 << endl; //0x148e06c70
	cout << ap2 << endl; //0x148e06c80
  // stack은 변수의 주소 값이 촘촘하게 내려가면서 할당이 되지만
  // Heap은 특성상 일정한 간격을 두면서 위로 올라간다.
```

### static(global) 메모리 영역

- 프로세스 메모리에서 일반적으로 Stack frame이 가장 위에 있고 밑으로 할당 되는 식으로 된다.
- Heap은 밑 부분에서 위로 할당 되는 식이다
- Heap메모리 영역 보다 더 밑에 static(global) 영역이 있다.

```cpp
  int a;
  int main(){
    int b;
    int *cp = new int;
    cout << &a << &b << cp; // b(Stack) > cp(Heap) > a(global / static)
  }
```
